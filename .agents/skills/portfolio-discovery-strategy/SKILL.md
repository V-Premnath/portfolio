# Portfolio Discovery & Strategic Positioning

The Discovery Strategy skill extracts the essential ingredients needed to craft a distinguished, magnetic portfolio that converts casual visitors into interview requests, freelance inquiries, or high-value partnerships.

<HARD-GATE>
You MUST complete the Discovery Brief and receive explicit approval from the user on the chosen **Brand Archetype**, **Target Audience**, and **Primary Conversion Goal** before proceeding to design tokens or code scaffolding.
</HARD-GATE>

---

## The Discovery Process

### Step 1: Analyze Archetype & Goals
Consult the [Archetype Rubrics Reference](./references/archetype-rubrics.md) and present the structured 5-point questionnaire to the user:

1. **Role & Archetype**: Determine which archetype fits the user best (Creative Technologist, Systems Architect, Product Builder, AI/ML Specialist, Minimalist Craftsperson, or Consultant).
2. **Target Audience**: Understand who is making the hiring/purchasing decision.
3. **Core Superpower / Value Proposition**: What is the single biggest technical or creative advantage they bring to the table?
4. **Flagship Projects (2–4 items)**:
   - Project Name & One-line elevator pitch.
   - Core tech stack used.
   - Quantifiable impact or technical breakthrough (e.g., "Scaled to 50k DAU", "99.99% uptime", "Reduced load time by 60%").
   - Live URL / GitHub link / demo status.
5. **Primary Conversion Action**: The exact next step (e.g., schedule a discovery call, email directly, view GitHub, download CV).

## Anti-Patterns & Red Flags

| Red Flag / Assumption | Reality | Correct Action |
| :--- | :--- | :--- |
| *"I'll assume they want a generic dark portfolio with standard sections."* | Every developer has a distinct strength (systems vs UI vs product). One-size-fits-all designs look amateurish. | Match the design archetype to their actual technical focus. |
| *"Let's list all 25 projects they've ever touched since college."* | Portfolio clutter dilutes perceived skill. 3 exceptional case studies outperform 20 mediocre homework assignments. | Filter strictly for the top 3-4 flagship projects. |
| *"We don't need a clear CTA; visitors can just find the email in the footer."* | Recruiters and clients scan in under 15 seconds. If the CTA isn't immediately obvious, conversion drops by 70%. | Position clear primary CTAs in both Hero and sticky Navigation. |

## Deliverable: The Discovery Brief

At the conclusion of this skill, format and present the summary brief:

```markdown
### 🎯 Portfolio Discovery Brief

- **User / Brand Name**: [Name]
- **Professional Title**: [e.g., Senior Full-Stack Engineer & Creative Developer]
- **Selected Archetype**: [e.g., Product Builder / SaaS Architect]
- **Target Audience**: [e.g., Hiring managers at Series A-B startups]
- **Core Value Proposition**: [e.g., "Building resilient, full-stack web applications that scale from 0 to 100K users."]
- **Primary Conversion CTA**: [e.g., "Get in Touch" / Calendly Modal / Email]
- **Flagship Projects**:
  1. **[Project 1]**: [Elevator pitch] — Impact: [Metric]
  2. **[Project 2]**: [Elevator pitch] — Impact: [Metric]
  3. **[Project 3]**: [Elevator pitch] — Impact: [Metric]
- **Key Skills / Tech Stack**: [Frontend, Backend, Cloud/DevOps, Tools]
```

### Verification Gate
STOP and ask: *"Does this Discovery Brief accurately capture your vision and positioning? Once you confirm, we will proceed to Phase 2: Design System & Visual Tokens."*
